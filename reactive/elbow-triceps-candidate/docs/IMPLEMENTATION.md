# 精细版实现

数据流：`sources/*.stl → build_studio.py → .blend / .glb / structures.json → GLTFLoader → 关节曲线 + 相邻形态键 → WebGL`。

源网格身份由 `sources/provenance.json` 映射。清理/降面、肌腱分区、纹理与动画都在 Blender 中生成，输出可编辑源文件，不依赖网页临时画出假模型。

标准单位为米。Blender 局部 `[x,y,z]` 导出为 glTF `[x,z,-y]`。骨骼保持刚性；肌肉与肌腱使用 24 个形态目标，网页逐角度插值相邻两组位置与法线数据。起止点、肌腹端点使用同步导出的动画空对象。

Three.js 0.180.0 运行库本地保存。物理材质包含纤维颜色/法线/粗糙度与胶原法线；方向光形成实时接触阴影。暂停时恢复较高像素采样；播放时使用较低采样并间隔更新阴影，保留同一份模型和材质。

浏览器测试使用真实鼠标/触摸事件检查画布拾取，并单独验证角度滑块、动画往返、结构显隐、展开精确复位和足印坐标。手机是 Chrome 移动视口触控仿真，不代表实体 Safari/Android 验收。


## 起点校准版

`attachment-landmarks.json` 保存六个肌头的候选部位、区域及检查视角。`attachment_geometry.py` 在指定区域内约束骨面接触顶点，采用平滑权重过渡到原有形变。肱肌与三头肌在骨干部采用源骨面切平面约束，减少插值穿过肱骨；靠近肘部解除该近似约束。17 个解剖结构不变，6 个 `annotationOwner` 标注网格单独管理，避免覆盖肌肉的稳定 ID。

起点检查的显隐属于临时观察模式；进入时保存视角、展开值，退出时恢复。肌腱和肌肉半透明，骨面保持不透明。代表点遵循深度遮挡，避免把后方的点画在前方骨头上造成误读。标注网格随所属骨骼的展开偏移移动，不随肌肉偏移。

几何检查直接读取保存后的 Blender 成品；浏览器检查将 Blender 中固定接触样本映射到实际 GLB 顶点，检查 49 个角度的漂移。旧长头标记的失配用作已知失败对照，防止检查只验证“标记贴在某块骨上”。解剖审核仍为独立步骤。


## 03.1 肌层贴合

移除原二头肌 13 mm 的前向分离项，改为最大 2 mm 的局部主体余量；保留两肌头的左右层次分配。二头肌、肱肌采用共享的主体位移趋势，远端仍过渡到各自的刚体附着。肱肌朝骨面的源表面法线用于区分贴骨面与外侧肌腹，在候选范围内保持较宽的接触。

按每个角度的肱肌实际形变网格建立查询，限制二头肌深面进入肱肌的程度，使用 1 mm 的局部几何避让余量。查询与修改作用于真实顶点及形态键，源码、Blender 与 GLB 保持一致。它不是筋膜厚度测量、完整碰撞解算或生理肌力模型。相关组织仍为独立对象。
